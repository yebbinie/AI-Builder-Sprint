# 초하루 (Chohyaru)

매달 첫날, 지난달에 내가 쓴 일기로 만든 편지가 도착하는 일기 앱.

**한 줄 소개**: 내가 나한테 보낸 편지를, AI가 한 달 뒤에 배달한다.
AI는 위로를 만들지 않는다. 사용자가 이미 써둔 문장을 찾아 되돌려줄 뿐이다.

2026 AI Builder Sprint 예선 제출작

---

## 핵심 기능

- **일기 작성 & 저장**: 텍스트 직접 입력, 또는 사진 촬영/선택 후 OCR로 텍스트 자동 인식
- **편지 자동 생성**: 매달 1일, 지난달 일기를 분석해 그 사람의 목소리로 편지를 조립
  - 반복된 감정, 사라진 걱정, 해결된 걱정, 담담하게 적은 노력, 좋았던 날 — 5가지 신호를 코드+LLM으로 추출
  - 편지에 인용된 문장은 원본 일기와 반드시 정확히 일치하도록 코드로 검증 (LLM이 지어낸 문장은 자동 제거)
- **문장 탭 → 원본 일기 이동**: 편지 속 인용 문장을 누르면 그 날짜의 실제 일기로 이동, 하이라이트 표시
- **편지함**: 받은 편지는 편지함에서 월별로 모아볼 수 있음
- **캘린더**: 쓴 날에만 점 표시 (안 쓴 날 표시·연속 기록·달성률 등 게이미피케이션 요소 일체 없음). 날짜를 누르면 그 날의 일기가 보임
- **지문/PIN 인증**: 기기 등록된 생체인증 우선, 미지원 시 PIN 대체
- **다크모드**: 라이트/다크 전환 지원
- **데모 모드**: 발표 시연을 위해 "매달 1일 자동 진입" 로직을 강제로 트리거하는 숨김 토글 (잠금 화면 앱 이름 1.2초 길게 누르기). 인증을 우회해 바로 편지 화면으로 진입하는 용도로도 사용 가능

## 기술 스택

- **프레임워크**: React Native (Expo SDK 54), TypeScript
- **저장**: AsyncStorage (기기 로컬, 서버 전송 없음)
- **인증**: expo-local-authentication (생체인증) + PIN fallback
- **OCR**: Upstage Document Digitization API
- **편지 조립 AI**: Google Gemini API (`gemini-3.5-flash-lite`, `gemini-flash-lite-latest` 별칭으로 호출)
- **UI**: react-native-svg (아이콘·봉투 일러스트), 커스텀 디자인 시스템 (외부 UI 라이브러리 미사용)

## AI 파이프라인 구조

```
지난달 일기
   ↓ ① 전처리 (코드)
   ↓ ② 태깅 (LLM — 감정·주제 라벨링)
   ↓ ③ 신호 추출
      ├─ 반복된 감정 / 사라진 걱정 / 해결된 걱정 (코드, 빈도·전후반 비교)
      └─ 담담한 노력 / 좋았던 날 (LLM)
   ↓ ④ 조립 (LLM — 핵심 조각 추출 → 문단 계획(코드) → 자연스러운 편지 조립)
   ↓ ⑤ 검증 (순수 코드 — 인용 문장이 원본과 정확히 일치하는지 대조, 불일치 시 자동 제거·재생성)
완성된 편지
```

⑤ 검증 단계는 LLM에 맡기지 않고 반드시 코드(문자열 대조)로만 처리합니다. 이 앱의 신뢰성이 여기에 달려 있습니다.

AI 호출이 실패하는 경우(네트워크 문제, API 한도 초과 등)에도 화면이 깨지지 않도록, 사전에 생성·검증된 편지로 자동 대체되는 안전장치가 있습니다.

## 로컬 실행 가이드

### 1. 필수 준비물

- Node.js (LTS 권장)
- 스마트폰의 **Expo Go** 앱 (App Store / Google Play, SDK 54 지원 버전)
- Upstage API 키 ([console.upstage.ai](https://console.upstage.ai)에서 발급, OCR용)
- Google Gemini API 키 ([aistudio.google.com](https://aistudio.google.com)에서 발급, 편지 조립용, 무료)

### 2. 설치

```bash
git clone https://github.com/yebbinie/AI-Builder-Sprint.git
cd AI-Builder-Sprint
npm ci
```

### 3. 환경변수 설정

프로젝트 루트에 `.env` 파일을 만들고 아래 내용을 입력합니다.

```
EXPO_PUBLIC_UPSTAGE_API_KEY=발급받은_Upstage_API_키
EXPO_PUBLIC_GEMINI_API_KEY=발급받은_Gemini_API_키
```

| 변수명 | 용도 | 발급처 |
|---|---|---|
| `EXPO_PUBLIC_UPSTAGE_API_KEY` | 손글씨/사진 일기 OCR 텍스트 인식 | console.upstage.ai |
| `EXPO_PUBLIC_GEMINI_API_KEY` | 편지 조립(핵심 조각 추출, 문단 생성) | aistudio.google.com (무료, 카드 불필요) |

두 키가 없어도 앱 실행 자체는 되며, 이 경우 OCR과 편지 실시간 생성 기능만 동작하지 않고 사전에 준비된 편지(실제 AI 생성 결과)가 대신 표시됩니다.

### 4. 실행

**네트워크 환경에 관계없이 안정적으로 연결하려면 tunnel 모드를 권장합니다.**

```bash
npx expo start --tunnel
```

터미널에 뜨는 QR 코드를 스마트폰의 Expo Go 앱(또는 iOS 기본 카메라 앱)으로 스캔하면 앱이 실행됩니다.

같은 Wi-Fi 네트워크에 있다면 아래 명령어도 사용 가능합니다:
```bash
npx expo start --clear
```

### 5. 데모 확인 경로

1. 잠금 화면에서 "초하루" 글자를 1.2초간 길게 눌러 데모 모드 활성화
2. 지문/PIN으로 잠금 해제 → 자동으로 편지 봉투 화면 진입
3. 봉투를 눌러 편지 열람
4. 편지 속 밑줄 그어진 인용 문장을 눌러 원본 일기로 이동, 하이라이트 확인
5. 캘린더에서 다른 날짜를 눌러 그날의 일기 확인
6. 홈 화면에서 "사진" 버튼으로 OCR 기능 확인 가능

### 실행이 안 될 때

1. QR 스캔 후 연결이 안 되면 `npx expo start --tunnel` 로 실행해주세요. 이 옵션은 네트워크 환경과 무관하게 연결됩니다.
2. 그래도 폰 연결이 어려우면, 아래 명령어로 웹 브라우저에서 확인 가능합니다.
   ```bash
   npx expo install react-dom react-native-web
   npx expo start --web
   ```
   단, 지문 인증은 웹에서 지원되지 않습니다. 잠금 화면에서 "초하루" 글자를 1.2초 길게 눌러 데모 모드를 켜면 인증 없이 편지 화면으로 바로 진입해 핵심 기능(편지 생성, 인용 문장 탭, 원본 일기 이동)을 확인하실 수 있습니다.
3. Expo Go 앱이 오래된 버전이면 최신 버전으로 업데이트해주세요 (SDK 54 지원 필요).

## AI를 어떻게, 왜 활용했는가

### AI가 반드시 필요했던 지점

- **신호 추출**: 한 달치 일기에서 "반복된 감정", "담담하게 쓴 노력", "해결된 걱정"을 찾아내려면 문장의 의미와 어조를 이해해야 합니다. 단순 키워드 빈도로는 "동아리 면접 봤음"처럼 짧고 담백하게 쓴 문장이 사실 큰 도전이었다는 걸 알아낼 수 없습니다.
- **편지 조립**: 서로 다른 날짜, 다른 맥락의 문장 조각들을 자연스러운 하나의 글로 엮는 작업은 규칙 기반 템플릿으로는 기계적으로 보일 수밖에 없습니다.

### 반대로, 일부러 AI에게 맡기지 않은 지점

- **⑤ 검증 단계는 100% 순수 코드**입니다. 편지에 인용된 문장이 원본 일기에 실제로 존재하는지는 문자열 대조로만 판단하며, "이 정도면 비슷하니 괜찮다"는 식의 LLM 판단을 배제했습니다. AI가 만든 결과를 AI가 다시 검수하게 하면 같은 방식으로 틀릴 위험이 있기 때문입니다.
- **반복된 감정 / 사라진 걱정 / 해결된 걱정**의 1차 후보 판별(빈도 집계, 전후반 비교)도 코드로 처리합니다. LLM은 이미 코드가 골라낸 후보에서 최종 표현만 다듬습니다.

### 실제 프롬프트 발췌 (편지 조립 단계, `src/pipeline/assemble.ts`)

```
# 절대 지켜야 할 핵심 규칙 1 — 날짜 순서 나열 금지
가장 흔하고 가장 나쁜 실패는 "1일엔 이랬고, 6일엔 이랬고..."처럼
날짜 순서대로 하나씩 요약해서 나열하는 것입니다. 이건 일기 요약이지 편지가 아닙니다.

# 인용 규칙 (매우 중요, 반드시 지킬 것)
절대로 quote 문장을 직접 타이핑하지 마세요. {{Q:ID}} 표시 하나로 대신합니다.
"적지 않았다", "말하지 않았다" 같이 인용의 존재를 부정하는 서술 금지 —
전부 실제로 그 사람이 쓴 문장입니다.
```

### 테스트·검증 산출물

개발 과정에서 검증 없이 LLM 결과를 그대로 썼을 때 아래와 같은 문제를 실제로 발견했고, 코드 기반 검증으로 자동 차단하도록 만들었습니다.

| 발견된 문제 | 실제 사례 | 대응 |
|---|---|---|
| 인용 오조합 (같은 날짜 신호 혼동) | 잠 관련 인용이 자료 폴더 문단에 잘못 삽입 | 신호별 고유 ID(`07-06a`, `07-06b`) 부여로 원천 차단 |
| 사실 왜곡(할루시네이션) | "가방 구석에서 지갑 찾았다" (원문: "그네 타다가 옆에 떨어뜨렸다") | 원본 대조 검증 강화, 신호 데이터에 구체적 맥락 보강 |
| 문장 반복·나열식 구조 | "~라고 적어놨더라"가 문단마다 반복 | 코드로 반복 표현 빈도 검사, 기준 초과 시 자동 재생성 |

검증은 `critical`(치명적 — 존댓말, 지어낸 내용, 인용 부족)과 `minor`(문체 반복 등)로 나누어 판단하며, 최대 재시도 후에도 실패하면 지금까지 생성된 결과 중 가장 나은 것을 사용해 서비스가 끊기지 않도록 설계했습니다. `docs/progress.md`에 시행착오 전 과정이 타임스탬프와 함께 기록되어 있습니다.

## 인간다움과 실현 가능성

- **인간다움**: 편지에 들어가는 모든 인용은 사용자가 실제로 쓴 문장 그대로입니다 (맞춤법, 말줄임표, "ㅋㅋ" 같은 표현까지 원문 그대로). AI는 그 문장들 사이를 자연스럽게 잇는 역할만 하며, 검증 단계가 이를 코드로 강제합니다. 그 결과 편지는 "AI가 요약한 나"가 아니라 "내가 실제로 쓴 나"로 읽힙니다.
- **실현 가능성**: 서버 없이 기기 로컬 저장(AsyncStorage)만으로 동작해 인프라 비용이 없고, 편지 생성에 쓰는 Gemini API는 무료 티어로 충분히 운영 가능합니다. OCR을 포함한 전체 파이프라인이 실기기에서 확인됐으며, 재시도·폴백 로직 덕분에 AI 호출이 실패해도 서비스가 멈추지 않습니다.
